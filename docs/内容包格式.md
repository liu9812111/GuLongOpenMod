# 内容包格式

一个内容包就是一个文件夹，放在 `游戏目录\Mod\Packs\` 下（仓库里是 `packs\`）。

```
packs\
  yinlong\                         ← 文件夹名 = 包的 id
    pack.json                      ← 必须有
    tables\                        ← 增量表（往游戏原表里加行 / 改行）
      SkillItem.txt
      NormalInventoryItem.txt
      RewardItem.txt
    tables_tc\                     ← 可选：繁体专用的增量表
    files\                         ← 按游戏资源路径放的文件
      Image\Icon\Item\itxk0002.png
    skillmod\                      ← 改招配置
      xk_yinlong.json
```

只需要放你用到的部分，没有的目录可以不建。

---

## pack.json

```json
{
  "id": "yinlong",
  "name": "亢龙有悔",
  "version": "1.0.0",
  "authors": ["James"],
  "description": "一句话介绍这个包做了什么。",
  "idPrefix": ["xk_", "itxk"],
  "requires": [],
  "order": 0
}
```

| 字段 | 说明 |
|---|---|
| `id` | 包的唯一名字，英文小写，和文件夹名一致 |
| `name` | 显示用的中文名 |
| `version` | 版本号，改了内容就加一点，如 `1.0.0` → `1.1.0` |
| `authors` | 作者列表，**要写成 `[...]`** |
| `description` | 简介 |
| `idPrefix` | 你新增的东西（招式、道具、对话…）的 Id 都以这些前缀开头，避免和别人撞名。见下文「Id 前缀」 |
| `requires` | 依赖的其他包的 id，如 `["yinlong"]`。缺了会在日志里警告 |
| `order` | 加载顺序，数字小的先加载，默认 0。**后加载的会覆盖先加载的** |

## tables：增量表

游戏的数据（招式、道具、人物、对话、任务……）都在一张张表里，原表在游戏里，你看不到也不需要复制。
增量表只写 **你新增或要修改的行**，插件在游戏读表时合并进去。

**格式**：纯文本，**Tab 分隔**，**UTF-8** 编码，`#` 开头的行是注释。文件名 = 表名，如 `SkillItem.txt`。

- 第一行（非注释）是 **表头**：原表的英文列名，**只写你用到的列**，顺序随意，**必须有 `Id`**。
- 下面每行一条数据：
  - **Id 原表里没有 → 新增一行**。没写的列留空。
  - **Id 原表里已有 → 修改那一行**。只改表头里写了的列，其他列保持原样。

例 1：新增一本书（`NormalInventoryItem.txt`）

```
# 注释随便写
Id	Name	Story	Price	Category	Rarity	Icon	Skill	WeaponType
itxk0002	亢龙有悔	「亢龙有悔，盈不可久。」……	5000	FightBook	2	itxk0002	xk_s0002	Fight
```

例 2：只改原版某个招式的伤害（`SkillItem.txt`）

```
Id	BaseDamage
Fight_s0016	40
```

**小贴士**

- 用 Excel / WPS 编辑也可以，保存时选「文本文件（制表符分隔）」，并确认编码是 UTF-8。
- 某格想留空就两个 Tab 之间什么都不写。修改原版行时，想把某格 **清空** 也是这样写（表头里要有这一列）。
- 想新增一行而且和原版某行很像（比如照抄推掌），最省事的办法：用 `tools/validate.py --dump` 导出合并后的整表，找到那行复制过来，改 Id 和要改的列。
- 繁体：`tables\` 里的表简繁通用。如果你写的文字想给繁体版单独一份，在 `tables_tc\` 放同名表，繁体版就会用它代替。

## files：按路径提供的文件

`files\` 下的路径 = 游戏读资源时用的路径。放进去的文件会 **代替或新增** 同路径的游戏资源。

| 放什么 | 路径 |
|---|---|
| 道具图标 | `files\Image\Icon\Item\{Icon列}.png` |
| 全身立绘 | `files\Image\FullProtrait\{头像Id}_0.png` |
| 半身立绘 | `files\Image\HalfProtrait\{头像Id}_0.png` |
| 头像 | `files\Image\HeadProtrait\{头像Id}_0.png` |
| 剧情演出 | `files\Config\Cinematic\{演出Id}.json` |
| NPC 行程 | `files\Config\Schedule\{Id}.json` |
| 战斗配置 | `files\Config\Battle\Area(SC)\{战斗Id}.json` |
| 背景音乐 | `files\Resources_Audio\BGM\{曲名}.ogg`（也支持 .wav / .mp3，替换同名原曲） |

图片用 PNG，尺寸尽量和原版同类图片一致。

> 不要把游戏原有的图片、音频放进要公开的包里。替换原版资源只做给自己玩的话，放在本地 `Mod\Packs\` 就好。

## skillmod：改招

在原版招式演出的基础上借特效、改颜色、调大小，生成新的招式演出。格式见 [改招.md](改招.md)。
文件名就是生成的演出名，SkillItem 表的 `AnimationName` 列填它。

## Id 前缀

所有人的内容最后会装在一起，新增的 Id 撞了就会互相覆盖。所以每个包要登记自己的前缀：

- 选一个短而独特的前缀，比如名字拼音缩写加下划线：`zs_`（张三）。
- 你新增的招式、道具、奖励、对话、任务…… Id 都用它开头：`zs_s0001`、`zs_book01`、`zs_book01_get`。
- 在 [Id前缀登记.md](Id前缀登记.md) 里登记一行，提交时一起提交。
- 前缀属于**作者**：你自己做的多个包可以共用同一个前缀（`authors` 里有同一个人即可），但不能和别的作者的前缀重叠。
- 修改原版的行不受限制（Id 本来就是原版的）。

插件和校验工具都会检查：新增的 Id 没用自己的前缀会给出警告 / 错误。

## 加载顺序和冲突

- 包按 `order` 从小到大加载，`order` 一样按文件夹名排序。
- 两个包改了 **同一张表的同一行**：后加载的为准，日志里会有警告。
- 两个包放了 **同一路径的文件**：后加载的为准，日志里会有警告。
- 游戏自带的 `Mod\Config\TextFiles(SC)\` 整表替换仍然有效，内容包的增量行会合并在它的基础上。
